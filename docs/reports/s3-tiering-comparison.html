S3 storage tiering: four approaches compared

Splunk SmartStore · ClickHouse S3 disk + TTL · OpenSearch searchable snapshots · OpenSearch writable warm — prepared for ironlog, updated 2026-11-03

Bottom line. Requirement: data older than ~90 days lives in S3, local disk is only a cache, no full local copy.
  • SmartStore and ClickHouse S3 disk + TTL meet it today, automatically.
  • OpenSearch writable warm meets it architecturally (S3 authoritative, local block cache, still writable), but self-managed open source is experimental (flag off by default, no docs page) and has no automation: one manual POST /{index}/_tier/warm per index. Automation via ISM exists only on Amazon OpenSearch Service (GA Dec 2025, OI2 instances, no GovCloud region at launch).
  • Searchable snapshots meet the cost goal but data becomes read-only.
  • ironlog already runs ClickHouse 24.8; its S3 tier is written but disabled (clickhouse/config.d/20-storage-s3.xml.disabled).

Remote-backed storage (GA since 2.10) was dropped as a column: it keeps a full copy on local disk, so it is durability only. It is the prerequisite layer under writable warm.

Writable warm, in depth

How it works (open source, 3.9.0 source code)

  1. Enable: start every node with opensearch.experimental.feature.writable_warm_index.enabled=true. Without it the _tier REST handlers are not registered (ActionModule.java:1146).
  2. Prerequisites: the index must use remote-backed storage (validator rejects: "does not have remote store enabled"); at least one node with the warm role ("no nodes found with the warm role").
  3. Move: POST /{index}/_tier/warm sets index.warm=true, index.composite_store.type=tiered-storage, index.tiering.state=HOT_TO_WARM, forces replicas to 1, and reroutes. Shards relocate to warm nodes. No data is copied to S3 during the move: it is already there.
  4. Complete: cluster manager watches routing changes; when every shard is on a warm node, state becomes WARM. In-progress moves are rebuilt after a cluster-manager failover.
  5. Serve: TieredDirectory writes new files locally, uploads them to the remote store, then switches them to remote. Reads fetch 8 MiB blocks into the FileCache on a miss.
  6. Back: POST /{index}/_tier/hot reverses it; POST /_tier/_cancel/{index} undoes an in-progress move.
