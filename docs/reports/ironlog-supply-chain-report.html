Licensing findings

FOSS describes freedoms to use, study, modify and redistribute software; it does not mean hosting/support costs zero. The Open Source Initiative (OSI) maintains criteria and approved licenses. The earlier SSPL exception for MongoDB is no longer needed: MongoDB left the stack with HyperDX on 2026-11-03. Primary upstream licenses do not establish all unmeasured dependency licenses. Receiving organizations may apply their own criteria. RHEL subscriptions supply support/maintenance entitlements; see Red Hat subscription guide.

FOCI findings

FOCI means Foreign Ownership, Control, or Influence. Under DCSA's framework, review concerns foreign interests' direct or indirect power over company management/operations and resulting classified-contract risks. Nationality of contributors or historical project origin alone is not a formal determination. FOCI concerns and mitigation are entity- and contract-specific; a public software license does not resolve them. DCSA explanation, DCSA mitigation process.

What the SBOM establishes

All three currently referenced ARM64 runtime images were scanned with Syft 1.56.0 on 2026-11-03 and identified by manifest digest: ClickHouse, Grafana and Vector. Result: 2,074 detected package occurrences (ClickHouse 111, Grafana 1,878, Vector 85), 8,406 file-evidence components and three operating-system records: 10,483 CycloneDX components. Counts are not deduplicated across images and are not license approvals. File-evidence counts are not comparable with the 2026-11-02 run, which recorded far fewer file components per image.

Grafana's count is mostly Go modules (1,846) compiled into the binary. Exact shipping RHEL AMI, host RPMs and the pinned Grafana plugin artifact were not scanned. Scanner license fields are incomplete and sometimes opaque hashes. Release SBOM therefore remains incomplete despite full current runtime-image scan coverage. No old AMI is claimed current, scanned, running or retained.

Current public-image snapshot is not proof of packages shipped in a previous AMI: major/patch tags can change. Exact scan references and timestamps are in scan summary. No runtime, cloud infrastructure, image pinning or private-artifact checks were changed.

Closure requirements

  1. Preserve required upstream notices, license texts and corresponding-source availability. Ironlog itself is excluded as a separate software product.
  2. Resolve build-tool licensing separately if the procurement policy extends to build tooling.
  3. Complete release-specific host, plugin and transitive package evidence using SBOM instructions; review unknown licenses.
  4. Obtain current beneficial-ownership, board/voting, foreign-interest and access/control disclosures for relevant suppliers. Where applicable, use SF-328/supporting evidence and the designated security authority; do not infer a government determination from this review.
  5. Obtain customer procurement/security disposition, including any mitigation or accepted exceptions. Self-hosting, egress restrictions, reviewed builds and controlled updates help supply-chain risk but do not erase ownership.

Regenerate declared inventory

From repository root:

python scripts/generate-sbom.py

This verifies source paths and checks inventory image references against Compose and appliance Quadlets. Unknown versions/licenses stay unknown. Generator records Git HEAD plus dirty-tree status; existing uncommitted documentation/diagram work is not represented as a new source release.

Regenerate image evidence

Install an approved Syft release, then from repository root:

python scripts/scan-image-sboms.py            # syft on PATH
python scripts/scan-image-sboms.py --syft /path/to/syft --platform linux/arm64

This scans every runtime image in ironlog.inventory.json, writes one CycloneDX 1.6 file per component, records the resolved manifest digest in scan-summary.json, and removes scans of images no longer declared. A failed scan exits non-zero. Each scan is equivalent to:

syft scan 'registry:<image>:<tag>' --platform linux/arm64 --scope squashed \
  -o cyclonedx-json@1.6=component.cdx.json

If registry rate limits recur, use authenticated access or a known approved image archive, and record actual digest and provenance. Do not substitute an unverified similarly named repository. Offline archives can be scanned with syft scan oci-archive:/path/image.tar -o cyclonedx-json@1.6=component.cdx.json.

CI

.github/workflows/sbom.yml runs on pushes and pull requests that touch image references or the inventory, and on manual dispatch. It runs generate-sbom.py (which fails on inventory/Compose/Quadlet drift), scans the repository directory with Syft, and uploads both as a 30-day workflow artifact. Manual dispatch with scan_images also runs scan-image-sboms.py. CI output is not committed back to the repository.

Complete a release-specific SBOM

  1. Record selected RHEL AMI ID/owner, build Git revision, architecture, RPM repositories and exact installed RPM NEVRA/license inventory. On the built host, capture rpm -qa --qf '%{NAME}\t%{EPOCHNUM}:%{VERSION}-%{RELEASE}\t%{ARCH}\t%{LICENSE}\n'.
  2. Scan approved base/appliance filesystem and each actually baked image or saved archive. Include final host RPMs, container base packages, static libraries and bundled application dependencies; capture unresolved findings.
  3. Capture actual datasource plugin.json version and scan the unpacked plugin/backend. Complete exact source mapping for bundled binaries.
  4. Reconcile inventory to final artifact identities and preserve provenance, license texts/notices and required corresponding source. Record analyzer versions and any exclusions; do not label unknown dependencies complete.
  5. Obtain supplier ownership/control disclosures and designated customer security/procurement review. An SBOM never establishes FOCI clearance.

These are release-evidence instructions, not new checksum/bucket-owner gates in Ironlog's build or private-artifact workflow. No AWS resources were launched.
